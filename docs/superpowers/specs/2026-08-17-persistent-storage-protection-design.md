# 持久化存储保护设计

## 目标

在设置页展示当前站点存储使用量、浏览器分配配额和持久化保护状态，降低设备空间紧张时账目及照片被浏览器自动回收的风险。

## 交互

- 设置页加载时读取 `navigator.storage.estimate()` 与 `navigator.storage.persisted()`。
- 尚未持久化时自动调用一次 `navigator.storage.persist()`；浏览器拒绝不阻塞页面使用。
- 显示“已保护”“未保护”或“当前浏览器不支持”，同时显示已用空间与总配额。
- 未保护时提供“重新申请”按钮；点击后重新申请并刷新状态。
- 明确提示持久化保护不是备份，用户主动清除站点数据仍会删除本地内容。

## 结构

新增独立的存储状态模块，负责浏览器 API 访问、字节格式化和错误兜底。设置页只负责展示状态与触发申请，避免把浏览器兼容逻辑堆入页面。

## 异常处理

- 浏览器缺少 StorageManager API 时显示“不支持”，不抛出页面错误。
- 配额读取或持久化申请失败时显示安全提示，备份、主题和账本功能继续可用。
- 配额属于当前来源；`localhost` 与 `127.0.0.1` 的统计互不共享。

## 测试

- 覆盖配额换算、已持久化、申请成功、申请被拒绝及 API 不支持。
- 设置页验证状态文案与重新申请入口。
- 运行全量单元测试和生产构建。
