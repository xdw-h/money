# 内置彩色图标目录设计

## 目标

在 GitHub Pages 静态站点中内置约 100 个 Fluent Emoji Flat 彩色图标。用户首次访问网站时随应用资源一次下载，之后直接按分类点选，无需安装应用、逐个搜索或再次请求 Iconify。

## 使用体验

- “常用”页改为餐饮、购物、交通、住房、医疗、学习、娱乐、旅行、收入、宠物 10 个分组。
- 每组约 8–12 个图标，总量控制在约 100 个。
- 打开图标选择器时立即展示完整目录，不显示联网加载状态。
- 在线搜索继续保留，仅用于内置目录没有覆盖的图标。
- Emoji 页和历史 MDI、Tabler 图标继续兼容。

## 资源与缓存

- 构建前从 Fluent Emoji Flat 选定并固化 SVG 数据，生产运行时不请求 Iconify 获取内置图标。
- 内置 SVG 作为 TypeScript/JSON 静态模块进入 Vite 构建产物，GitHub Pages 首次访问时随站点资源下载。
- 现有 PWA Service Worker 缓存构建资源；安装到桌面为可选操作，不是使用内置图标的前提。
- `IconDisplay` 先读取内置图标映射，再读取 IndexedDB，最后才为非内置在线图标请求网络。
- 用户选中内置图标后仍保存统一的 `iconify:fluent-emoji-flat:<name>` 键，不改变分类、账本和流水数据结构。

## 目录结构

- `bundledIconCatalog.ts`：分组名称、图标键、搜索别名和展示顺序。
- `bundledIconAssets.ts`：构建时固化的安全 SVG body、宽高和前缀。
- `IconDisplay.vue`：内置资源、本地缓存、在线资源三级解析。
- `EmojiPickerField.vue`：分组展示与选择，不负责下载内置资源。

## 备份

- ZIP 备份只导出实际引用且不属于内置目录的图标资源；内置图标只保存稳定键，不重复写入 SVG。
- 恢复时若图标属于内置目录，可直接使用站点内置 SVG；不存在于当前版本的历史在线图标继续从备份的 `icons.json` 恢复。
- v1、v2 备份兼容规则保持不变。

## 安全与许可

- 生成内置资源时复用 SVG 安全校验，只接受 Fluent Emoji Flat 前缀和允许的 SVG 元素。
- Fluent Emoji Flat 使用 MIT 许可证，在项目第三方许可说明中记录来源和许可证。
- 不在运行时执行远程 SVG 脚本或外部引用。

## 体积与性能

- 内置目录控制在约 100 个图标，生产包预计增加 150–300 KB 原始体积，gzip 后更小。
- 图标资源采用一个独立懒加载代码块；只有打开图标选择器或显示已使用的内置图标时加载。
- 不发起约 100 次独立网络请求，不需要 IndexedDB 预热。

## 测试与验收

- 测试 10 个分组和图标总量范围，确保键唯一且全部属于 Fluent Emoji Flat。
- 测试内置图标在 `fetch` 不可用时仍能渲染和选择。
- 测试 `IconDisplay` 对内置、IndexedDB、历史 Emoji 三种来源的解析顺序。
- 测试备份只包含实际引用资源，并兼容历史在线图标。
- 生产构建后在 GitHub Pages 路径模式下验证资源地址、离线重载和手机端网格。
